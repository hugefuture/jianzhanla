# 新增一个业务模块（四层结构实操指南）

以内置样例「**通知公告**」（`biz.Notice`）为蓝本。照抄这个模块改字段名，即可在 10 分钟内产出一个规范的业务模块。

## 0. 约定

| 项 | 约定 |
|---|---|
| 表名 | `sdccc_` 前缀（历史技术前缀，对外名称已改为「建站啦后台管理系统」，前缀不动） |
| 权限标识 | 路由路径把 `/` 换成 `:`，如 `biz/notice/save` → `biz:notice:save` |
| 业务模块 | 放 `app/admin/controller/biz/`，与系统模块 `system/` 区分 |
| 目录层级 | controller → service → dao → model，**不允许跨层调用**（controller 不直接碰 model） |

## 1. 建表 + 种子（sql/）

参考 `sql/migrate_notice.sql`，一次写齐四件事：

```sql
-- 1) 业务表：必须带 dept_id（数据权限维度）与 create_by（归属人）
CREATE TABLE IF NOT EXISTS `sdccc_sys_notice` (...);

-- 2) 字典（下拉选项）：sys_dict_type + sys_dict_data
-- 3) 菜单：目录 M -> 页面 C -> 按钮 F，并给超管角色授权 sys_role_menu
-- 4) 演示数据
```

> 菜单 `component` 必须与前端文件路径一致：`business/notice/index` ↔ `frontend/src/views/business/notice/index.vue`。
> 菜单 `perms`（`biz:notice:list`）必须与后端路由推导出的权限点一致，否则会被 403。

## 2. Model（`app/admin/model/SysNotice.php`）

```php
protected $name = 'SysNotice';          // SysNotice -> sdccc_sys_notice
protected $autoWriteTimestamp = 'datetime';
protected $append = ['type_text'];      // 派生字段，列表直接展示
public function getTypeTextAttr($v, array $data = []): string { ... }
```

职责：只描述数据结构与派生字段，**不写查询、不写业务规则**。

## 3. Dao（`app/admin/dao/SysNoticeDao.php`）

```php
protected array $search = ['title' => 'like', 'status' => '=', 'create_time' => 'time'];
protected string $order = 'is_top desc, id desc';
protected bool $dataScope = true;       // 开启数据权限，列表自动过滤
protected string $scopeDeptField = 'dept_id';
protected string $scopeUserField = 'create_by';
```

`$search` 支持的匹配类型：`=` / `like` / `in` / `between` / `>=` / `<=` / `time`（日期区间）。

## 4. Service（`app/admin/service/SysNoticeService.php`）

```php
protected array $allowFields = ['title', 'type', 'content', 'status', 'is_top', 'dept_id', 'remark'];
protected array $required = ['title'];

protected function beforeCreate(array &$data): void {
    $user = request()->user ?? [];
    $data['create_by'] = (int) ($user['id'] ?? 0);        // 自动填充创建人
    if (empty($data['dept_id'])) $data['dept_id'] = (int) ($user['dept_id'] ?? 0);
}
```

可用钩子：`beforeCreate` / `afterCreate` / `beforeUpdate` / `afterUpdate` / `beforeRemove` / `afterRemove`。
需要的非表字段（如 `role_ids`）声明到 `$extraFields`，会自动传给钩子而不写入主表。

## 5. Controller（`app/admin/controller/biz/Notice.php`）

```php
class Notice extends CrudController {   // 继承即得 list/read/save/delete/status
    public function __construct(App $app) {
        parent::__construct($app);
        $this->service = SysNoticeService::getInstance();
    }
    public function publish(): Response { ... }   // 只写业务独有接口
}
```

## 6. 路由（`app/admin/route/app.php`）

```php
Route::get('biz/notice/list', 'biz.Notice/index');
Route::get('biz/notice/read/:id', 'biz.Notice/read');
Route::post('biz/notice/save', 'biz.Notice/save');
Route::post('biz/notice/delete', 'biz.Notice/delete');
Route::post('biz/notice/publish', 'biz.Notice/publish');
```

路由写在带 `Token` + `OperLog` 中间件的分组内，自动获得鉴权与操作日志。

## 7. 前端

1. `src/api/index.js` 追加接口封装；
2. `src/views/<模块>/<页面>/index.vue` 新建页面（`component` 路径对应）；
3. 按钮级权限用 `hasPerm('biz:notice:save')` 控制显隐。

前端无需改路由表——菜单由后端下发，动态路由自动挂载。

## 数据权限说明

角色可在「系统管理 → 角色管理」配置数据范围：

| 值 | 含义 |
|---|---|
| 1 | 全部数据 |
| 2 | 自定义部门（含子部门） |
| 3 | 仅本部门 |
| 4 | 本部门及以下 |
| 5 | 仅本人 |

只要 Dao 打开 `$dataScope = true`，列表即自动生效；超级管理员（角色编码 `super`）始终放行全部。
